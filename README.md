# 💇‍♀️ Salon Booking Bot

Telegram-бот для онлайн-записи клиентов в салон красоты (Фарбування волосся, Стрижка, Манікюр).
Весь интерфейс бота — на украинском языке. Python 3.11+, `aiogram` 3.x, SQLite, APScheduler.

## Возможности

**Клиент**
- Главное меню: «📅 Записатися на послугу», «📋 Мої записи», «💇‍♀️ Послуги та ціни», «📍 Контакти та адреса».
- Запись за 6 шагов (FSM): услуга → мастер (или «Будь-який вільний майстер») → дата (ближайшие 14 дней, только дни со свободным временем) → время (динамический расчёт слотов) → имя и телефон → подтверждение.
- Имя подтягивается из Telegram (можно изменить), телефон — кнопкой «📱 Поділитися номером» или вводом вручную с валидацией; последний использованный номер предлагается повторно.
- «Мої записи»: просмотр предстоящих записей и отмена с подтверждением.
- Напоминания за 24 часа и за 2 часа до визита (с кнопкой отмены записи).
- Кнопки «⬅️ Назад» и «🏠 В головне меню» есть на всех экранах, кроме корневых меню (у них только выход/переходы вглубь); на шаге ввода телефона они выполнены кнопками обычной клавиатуры.

**Администратор** (`/admin`, только `ADMIN_IDS`)
- 📅 Расписание на сегодня / завтра / любую дату, фильтр по мастерам, карточка записи.
- Отмена любой записи (клиент получает уведомление) и ➕ ручное добавление записи (тот же пошаговый сценарий).
- 💇 Услуги: добавление, изменение названия / цены / длительности, скрытие. 👩‍🎨 Мастера: добавление, имя, услуги мастера, недельный график с перерывом, скрытие.
- 🚫 Закрытие дня, периода (отпуск) или временного окна для мастера; предупреждение, если на это время уже есть записи.
- 📣 Рассылка всем пользователям: предпросмотр, подтверждение, прогресс и итоговая статистика (доставлено / заблокировали бота / ошибки).
- Администраторы получают уведомления о новых записях и об освободившихся окнах (отмена клиентом).

## Быстрый старт

```bash
# 1. Python 3.11+ и виртуальное окружение
python3 -m venv .venv
source .venv/bin/activate            # Windows: .venv\Scripts\activate

# 2. Зависимости
pip install -r requirements.txt

# 3. Настройки
cp .env.example .env                 # Windows: copy .env.example .env
# впишите BOT_TOKEN (от @BotFather) и ADMIN_IDS (ваш ID можно узнать у @userinfobot)

# 4. Запуск
python main.py
```

При первом запуске автоматически создаются таблицы SQLite (`data/salon.db`) и тестовые данные: 3 услуги,
4 мастера и их расписание — бота можно сразу проверять. Остановка — `Ctrl+C`.

> Администратор должен хотя бы один раз нажать `/start` у бота, иначе Telegram не позволит боту писать ему первым.

## Настройки (`.env`)

| Переменная | По умолчанию | Описание |
|---|---|---|
| `BOT_TOKEN` | — (обязательно) | токен от @BotFather |
| `ADMIN_IDS` | пусто | Telegram ID администраторов через запятую |
| `TIMEZONE` | `Europe/Kyiv` | часовой пояс салона (расписание, напоминания) |
| `DB_PATH` | `data/salon.db` | путь к файлу базы (относительный — от корня проекта) |
| `LOG_LEVEL` | `INFO` | уровень логирования; лог пишется в консоль и в `logs/bot.log` |
| `BOOKING_HORIZON_DAYS` | `14` | на сколько дней вперёд можно записаться |
| `SLOT_STEP_MIN` | `30` | шаг сетки времени для слотов (минуты) |
| `MIN_LEAD_MINUTES` | `60` | за сколько минут до начала ещё можно записаться сегодня |
| `SALON_NAME`, `SALON_ADDRESS`, `SALON_PHONE`, `SALON_HOURS` | см. `.env.example` | данные для приветствия и раздела «Контакти та адреса» |
| `SALON_MAP_URL`, `SALON_LAT`, `SALON_LON` | пусто | ссылка на карту и/или геоточка, отправляемая в «Контактах» |

## Схема базы данных

| Таблица | Назначение |
|---|---|
| `users` | пользователи бота: `tg_id` (PK), имя, username, последние имя/телефон для автозаполнения, флаг `is_blocked` |
| `services` | услуги: название, цена (грн), длительность (мин), `is_active` |
| `masters` | мастера: имя, `is_active` |
| `master_services` | какие мастера выполняют какие услуги (M:N) |
| `work_schedule` | недельный шаблон: `(master_id, weekday 0=Пн…6=Нд)` → начало, конец, перерыв; нет строки — выходной |
| `time_off` | закрытые для записи дни (`start/end = NULL`) или временные окна мастера |
| `appointments` | записи: клиент, услуга, мастер, дата, `start_time`/`end_time`, цена и длительность на момент записи, `status` (`active`/`cancelled`), кто создал/отменил, флаги отправленных напоминаний |
| `meta` | служебное (флаг, что тестовые данные уже созданы) |

Даты хранятся как `YYYY-MM-DD`, время — как `HH:MM` в часовом поясе салона. Отмена — «мягкая» (`status = 'cancelled'`), история сохраняется.

## Как это работает

**Свободные слоты.** Для мастера и даты берётся рабочий интервал из `work_schedule`, из него вычитаются перерыв, закрытия из `time_off` и существующие активные записи. Слоты строятся по сетке `SLOT_STEP_MIN` от начала рабочего дня; слот подходит, если вся длительность услуги помещается в рабочее время и не пересекается ни с чем занятым. Записи «встык» (одна заканчивается, когда начинается другая) допустимы. Сегодня доступно только время не раньше `сейчас + MIN_LEAD_MINUTES`. Для «Будь-який вільний майстер» слоты объединяются по всем подходящим мастерам, а при выборе времени назначается наименее загруженный в этот день.

**Защита от двойного бронирования.** Проверка слота и вставка записи выполняются в одной транзакции `BEGIN IMMEDIATE`: SQLite сам выстраивает конкурентные запросы в очередь, второй клиент видит уже занятый слот и получает «цей час щойно зайняли» с возвратом к выбору времени. Дополнительно стоит уникальный индекс `(master_id, date, start_time)` для активных записей, а двойной тап по «Підтвердити» гасится блокировкой на пользователя. Это проверено тестом: 8 одновременных запросов на один слот → ровно одна запись.

**Напоминания.** Раз в минуту задача APScheduler спрашивает у БД, каким записям пора отправить напоминание (за 24 ч и за 2 ч), и помечает отправленные флагами в таблице `appointments`. Состояние живёт в базе, поэтому после перезапуска бота ничего не теряется и не дублируется. Если визит назначен менее чем за 24 часа, «24-часового» напоминания не будет; если бот был выключен и окно 24 ч пропущено, отправится только ближайшее актуальное. Недоставленные из-за сетевой ошибки повторяются, заблокированным пользователям — нет.

**FSM.** Состояния хранятся в `MemoryStorage`: после перезапуска бота прерываются только записи, находящиеся в процессе оформления (старые кнопки ответят «кнопка неактуальна»). Подтверждённые записи и напоминания лежат в SQLite. Если нужна устойчивость и этого, замените хранилище на `RedisStorage` в `bot/app.py`.

## Запуск как сервис (Linux, systemd)

```ini
# /etc/systemd/system/salon-bot.service
[Unit]
Description=Salon booking Telegram bot
After=network-online.target

[Service]
WorkingDirectory=/opt/salon_bot
ExecStart=/opt/salon_bot/.venv/bin/python main.py
Restart=always
RestartSec=5
User=salonbot

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload && sudo systemctl enable --now salon-bot
journalctl -u salon-bot -f
```

Резервная копия — достаточно копировать `data/salon.db` (лучше при остановленном боте или командой `sqlite3 data/salon.db ".backup backup.db"`).

## Частые вопросы

- **«Telegram rejected BOT_TOKEN»** — проверьте токен в `.env` (без кавычек и пробелов).
- **Кнопки «⬅️ Назад / 🏠 В головне меню» на шаге телефона выглядят иначе** — там Telegram требует обычную клавиатуру для кнопки «Поділитися номером», поэтому навигация сделана ею же.
- **Админ не получает уведомления** — он должен хотя бы раз написать боту `/start`; проверьте `ADMIN_IDS`.
- **Как поменять тестовые данные** — через `/admin` (услуги, мастера, графики). Чтобы начать с чистой базы, остановите бота и удалите `data/salon.db*`.
- **Хочу другой формат слотов** — меняйте `SLOT_STEP_MIN` (например, `15` или `60`).
